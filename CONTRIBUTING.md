# Contributing

Contributions are welcome in research methods, software, data quality, documentation, and security.

## Ground rules

- Use only public, lawfully accessible research data.
- Never submit patient-identifiable or confidential information.
- Link every factual claim to a stable source.
- Separate catalogue metadata from accepted evidence.
- Include limitations and negative results.
- Do not review your own research artifact.
- Do not describe experimental findings as clinical advice.
- Never commit secrets, private keys, wallet seed phrases, personal contact details, or local environment files.

## Software changes

Run `npm run protocol:test` and `npm run build` before opening a pull request. Onchain changes also require Anchor build, local-validator tests, threat-model review, and an independent security review before deployment.

## Research artifacts

A useful artifact identifies the research question, source set, inclusion criteria, method, result, uncertainty, limitations, and reproducible steps. Reviews should name the artifact they evaluated and disclose conflicts.
